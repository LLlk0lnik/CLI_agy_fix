# agyCLI — Windows 10/11 x64 (Intel/AMD, 64 бита)

Переносимый запуск обычного Antigravity CLI через собственный локальный шлюз и отдельную авторизацию. Запасной ACP-клиент также включён. Это не официальный дистрибутив Google; оригинальные бинарники Google не изменены.

```text
README.md
Run-AGY.cmd   — обычный CLI через VPN/шлюз
Run-ACP.cmd   — отдельный ACP-клиент
setup/               — Login и Check
app/                 — код, runtime, config и локальный профиль
docs/                — README-AI и сведения о компонентах
```

## Установка с самого начала

### 1. Получить agy — Antigravity CLI

Официальная инструкция и скачивание: [Google Antigravity](https://antigravity.google/docs/getting-started).
В этом архиве **agy 1.4.12 уже скачан** и находится в app/runtime/agy.exe. Поэтому для этой сборки отдельная установка CLI не нужна: используются именно вложенные бинарники, независимо от установленного в системе agy.

Если нужен и обычный системный agy, его официальный установщик запускается так:

```powershell
irm https://antigravity.google/cli/install.ps1 | iex
```

Это необязательный шаг и он может добавить agy в системное окружение пользователя. Наши запуски не вызывают установщик и не меняют PATH. Команда просто `agy` запустит обычную установленную версию, а не эту сборку.

### 2. Установить Python

Скачайте Python 3.11 или новее с [python.org](https://www.python.org/downloads/). Сторонние Python-пакеты и pip install не нужны.
При установке включите Python Launcher (команда py). Если установлен только python.exe, CMD-запуски попробуют его автоматически. Если Windows открывает Microsoft Store вместо Python, установите Python с python.org и включите launcher.

Проверьте:

```powershell
py -3 --version
```

### 3. Установить и настроить Happ

Скачать: [сайт Happ](https://happ.info/). Добавьте **свою** рабочую подписку/конфигурацию и выберите сервер. VPN-подписка и чужие данные входа в архив не включены.

Нужен локальный HTTP-прокси Happ. В app/config.json по умолчанию записано:

```json
{
  "http_proxy": "http://127.0.0.1:10809",
  "socks_proxy": "socks5h://127.0.0.1:10808",
  "default_model": "gemini-3.8-flash-high"
}
```

Проверьте реальные порты в своей версии Happ и при необходимости измените app/config.json. Эти номера были проверены на исходной macOS-конфигурации; Windows-версия Happ может использовать другие. Подойдёт и другой локальный HTTP-прокси на указанных портах. Программа не включает Happ автоматически.

Чтобы проксировался только этот запуск, Happ должен предоставлять локальный прокси без общесистемного VPN/TUN и системного прокси. Скрипты не переключают эти режимы. Если в Happ уже включён глобальный VPN, он продолжит действовать для остальных программ. Доступность режима локального прокси зависит от версии Happ.

### 4. Распаковать архив

Полностью распакуйте agyCLI-windows-x64.zip в доступную для записи папку, например C:/Tools/agyCLI-windows-x64. Не запускайте файлы прямо из ZIP, не используйте Program Files/защищённые папки и общий облачный каталог.

Откройте Windows Terminal/PowerShell и перейдите в распакованную папку. Примеры ниже выполняются из неё. 
### 5. Проверить установку и сеть

```powershell
.\setup\Check.cmd
```

Проверка ищет три бинарника, проверяет архитектуру, HTTPS через Happ и ACP initialize. На чистой сборке сообщение «NEXT: run Login» нормально: своего профиля пока нет. Проверка сама не входит в аккаунт.

### 6. Войти под своим аккаунтом Google

```powershell
.\setup\Login.cmd
```

Завершите вход в открывшемся браузере и дождитесь «Вход завершён». Если окно не открылось, используйте показанную ссылку входа. У браузера свои настройки сети; proxy-переменные действуют на агент, а не на уже открытый браузер.

Нужен собственный аккаунт с доступным действующим тарифом/проектом. Чужая подписка не передаётся вместе с архивом. Сборка не создаёт права доступа и не гарантирует, что любой аккаунт будет принят Google.

### 7. Запустить обычный интерфейс agy

```powershell
.\Run-AGY.cmd
```

Для работы с конкретным проектом сначала перейдите в его папку, затем вызовите запуск по полному пути:

```powershell
cd C:\Projects\MyProject
& "C:\Tools\agyCLI-windows-x64\Run-AGY.cmd"
```

Примеры аргументов:

```powershell
.\Run-AGY.cmd --continue
.\Run-AGY.cmd --print "Ответь одним словом: привет" --print-timeout 45s
```

В заголовке может отображаться Gemini API key. Это временный ключ локального шлюза; отдельный Google AI Studio API key создавать не требуется. Реальные запросы используют ваш отдельный OAuth-профиль.

## Что запускает каждый файл

| Файл | Назначение |
| --- | --- |
| Run-AGY.cmd | Штатный интерфейс agy CLI через отдельный локальный шлюз |
| Run-ACP.cmd | Простой текстовый клиент официального ACP-агента |
| setup\Login.cmd | Только отдельная браузерная авторизация |
| setup\Check.cmd | Проверка зависимостей, прокси и доступности профиля |

Каждый файл напрямую запускает соответствующую Python-программу. Запуски не перенаправляют друг на друга. Для ACP доступны /quit, /new, /models, /model ID; Enter в запросе разрешения означает отказ. Ctrl+C завершает отдельный запуск.

## Где данные и что изолировано

Папка app/profile появляется только после первого использования. Авторизация ACP: app/profile/gemini/antigravity-acp. История и настройки штатного CLI: app/profile/native-home. Диагностика ACP: app/profile/server.log. Keychain/Windows Credential Manager для ACP отключены; используется файловое хранилище.

На macOS файлы профиля создаются с ограниченными UNIX-правами. На Windows права наследуются от папки пользователя: не распаковывайте сборку в общую папку, файловый токен защищайте правами своей учётной записи.

Настройки окружения действуют только в процессе запуска и его потомках. Новые терминалы, Zed, системная сеть, shell-профили и уже установленный agy не меняются. В native agy HOME/USERPROFILE/APPDATA указывает на private profile: привычные Git/SSH-настройки домашней папки могут не обнаруживаться автоматически.

Это отдельный профиль, не виртуальная машина и не файловая песочница. У агента есть обычный доступ к выбранному проекту по его правилам разрешений. Дочерние программы, игнорирующие proxy-переменные, могут обращаться напрямую.

## Если не работает

- Python not found: установите Python и откройте новый терминал.
- Proxy unavailable: Happ должен работать; проверьте HTTP-порт в app/config.json.
- Authentication required: повторите setup\Login.cmd; не копируйте профиль друга.
- Account ineligible/403: Google не подтвердил доступ; смена прокси не гарантирует решение. Не меняйте платёжный профиль на основании одной такой ошибки.
- Model not found/404: проверьте Run-ACP.cmd и каталог /models; код API и модели могут меняться.
- Ошибка сертификата после установки Python: проверьте системные сертификаты/установку Python; TLS-проверку не отключайте.
- Для нейросети или разработчика откройте docs/README-AI.md; токены и полный server.log в чат не отправляйте.

## Как поделиться ещё раз

Лучше отправить исходный чистый ZIP. После входа **не архивируйте всю папку**: там уже есть ваши данные. Для чистой перепаковки:

```powershell
py -3 app/pack_clean.py
```

Архив будет в app/dist. Контрольные суммы пересчитываются. Скрипт берёт только явный список файлов, исключает profile, логи и кеши; app/config.json сбрасывает к публичному app/config.example.json. Не добавляйте личные данные в исходники и документацию. Проверка оригинальных файлов: `py -3 app/verify_package.py` (после изменения портов отличие app/config.json ожидаемо).

Версии: agy 1.4.12, ACP 1.4.5, оболочки 1.2.0. Проверены реальный ответ модели и чтение тестового файла на macOS ARM64. Общие Python-тесты проверяют 21 сценарий, включая Windows-пути и изоляцию переменных. **Windows x64 адаптирована, но на настоящей Windows не запускалась.** Это явно указано и в app/BUILD-MANIFEST.json.

countTokens не реализован (501). Все модели и функции CLI не проверены. Обновление Google может потребовать доработки; автоматическое обновление вложенного CLI в этих запусках отключено.
