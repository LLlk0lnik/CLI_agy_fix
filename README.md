# CLI_agy_fix

Две версии терминального ACP-клиента официального агента Google с локальным прокси и отдельным профилем:

- [macOS Apple Silicon](macOS/README.md)
- [Windows x64](Windows/README.md)

`agym`, `Run-AGY` и `Run-ACP` используют один путь: терминальный клиент → официальный Google ACP Server → Google. Механизм соответствует ACP-интеграции Zed; обёртка не читает OAuth-токены и не выполняет HTTP-запросы к API Google. SmartDNS и старый HTTP-шлюз удалены. Бинарники Google не изменены.

[Проверка исходников Zed, происхождения бинарников и ограничений](macOS/docs/ZED-ACP-AUDIT.md). Это независимый терминальный клиент, без гарантии отсутствия ограничений аккаунта.

## Получить проект

Крупные оригинальные бинарники хранятся в Git LFS. Установите Git LFS, только если его ещё нет; GitHub Desktop уже включает его. При клонировании через GitHub Desktop LFS-файлы обычно загружаются автоматически.

Для установленного Git LFS:

```bash
git clone https://github.com/LLlk0lnik/CLI_agy_fix.git
cd CLI_agy_fix
git lfs pull
```

ZIP через кнопку GitHub Download ZIP может содержать LFS-указатели вместо исполняемых файлов. Если бинарник имеет размер около 130 байт и начинается с `version https://git-lfs.github.com/spec/v1`, скачайте LFS-объекты через git lfs pull. Не запускайте такой файл.

После загрузки следуйте README соответствующей платформы. Не устанавливайте повторно существующие Python, Happ и agy; версия agy для этой сборки уже есть в runtime. Windows x64 адаптирована, но не проверена реальным запуском на Windows.

## Обновление до новой версии

Клон репозитория и есть установка, поэтому обновление — одна команда в терминале:

```bash
./macOS/agym update --check   # показать доступные версии, ничего не меняет
./macOS/agym update           # применить обновление
```

После `./agym install` то же доступно отовсюду как `agym update`. Что делает команда: `git fetch` текущей ветки, отказ при незакоммиченных правках в отслеживаемых файлах, fast-forward merge, догрузка изменившихся бинарников через Git LFS (только если версия agy/ACP изменилась), проверка `SHA256SUMS.txt` и печать перехода версий. `agym --version` показывает установленные версии обёртки, agy и ACP.

Локальный профиль `app/profile` и файл `app/config.json` обновление не затрагивает: `config.json` не входит в репозиторий, а значения по умолчанию берутся из `app/config.example.json`. Windows: `agym.cmd update` и `agym.cmd update --check`.

## Сборка новой версии

```bash
python3 tools/release.py macOS --version 2.0.0   # macOS
python3 tools/release.py Windows --version 2.0.0 # Windows
```

Скрипт пересчитывает SHA256 бинарников и `SHA256SUMS.txt`, обновляет `BUILD-MANIFEST.json`, прогоняет тесты и собирает чистый ZIP через `app/pack_clean.py`. Руками версии и хеши править не нужно.

## Быстрый старт с `agym` (macOS)

```bash
cd macOS
chmod +x ./agym ./Run-*.command setup/*.command app/runtime/*

# Добавить agym в ~/.local/bin для запуска из любой папки
./agym install

# Проверить готовность прокси Happ и окружения
agym check

# Авторизоваться в Google через браузер
agym login

# Запуск в проекте (без постоянных подтверждений прав)
agym -y
```

## Личные данные

В репозитории нет профилей, авторизации и истории. Каждый пользователь входит в свой Google-аккаунт и использует свою конфигурацию Happ. Папки app/profile, токены, логи, базы истории, кеши и ZIP-архивы исключены через .gitignore. Не используйте git add -f для этих файлов.

Только публичные настройки прокси из config.example.json входят в исходную конфигурацию. Не записывайте секреты в исходники, README и отслеживаемые конфиги.

Исходная рабочая папка и личный профиль владельца остаются локально, отдельно от этого клона. Для отправки чистой сборки используйте app/pack_clean.py выбранной платформы, а не архивирование рабочей папки целиком.

## FAQ (Часто задаваемые вопросы)

### Нужно ли иметь `agy` на машине изначально?
**Нет, не нужно.**
Официальные ACP Server 1.4.5 и его harness уже находятся в `app/runtime/`; оригинальный `agy` 1.4.12 также оставлен в пакете. Скрипт `agym` вызывает вложенный Google ACP Server и не зависит от наличия или отсутствия `agy` в системе. Если у вас уже установлен системный `agy`, они не конфликтуют: `agy` запустит системную версию, а `agym` — терминальный ACP-клиент с отдельным профилем и прокси Happ.

### Могу ли я запускать `agym` из любой папки проекта?
**Да, из любой.**
После выполнения `./agym install` (или добавления симлинка в `~/.local/bin/agym`, если путь в вашем `PATH`) команда `agym` доступна глобально. Вы можете перейти в каталог любого проекта (`cd ~/Projects/my-app`) и вызвать `agym` (или `agym -y`) — агент запустится в текущей папке и будет работать с файлами именно этого проекта.
