# agyCLI: официальный Google ACP в терминале

`agym` запускает оригинальный Google Antigravity ACP Server 1.4.5 из ACP Registry и общается с ним по JSON-RPC через stdin/stdout. Это тот же механизм интеграции, который использует Zed. Вход, токены, обновление токенов, модели, инструменты и обращения к Google выполняет официальный агент.

Собственный HTTP-шлюз, чтение OAuth-токенов обёрткой и SmartDNS удалены. Старый `app/agy_native.py` оставлен только как совместимый вход в ACP-клиент.

## Запуск

```bash
cd macOS
./agym check --offline
./agym check
# После восстановления доступа:
./agym login
./agym
```

Одиночный запрос: `./agym -p "Ответь OK"`. Выбор модели: `./agym --model ID`; доступные ID показывает `/models`. Пустой `default_model` оставляет выбор официальному агенту. Клиент не переименовывает модели и не выдаёт себя за Zed.

`./agym -c` продолжает последнюю ACP-сессию в текущей папке. `./agym --conversation ID` загружает указанную ACP-сессию. Старые ID диалогов нативного CLI не преобразуются в ACP-сессии. В чате доступны `/new`, `/models`, `/model ID`, `/quit`.

`./agym yolo` или `-y` одобряет предлагаемые агентом разрешения типа `allow_once`. Без этого флага клиент спрашивает разрешение; Enter означает отказ. Произвольные прежние флаги нативного CLI, например `--settings`, больше не передаются: интерфейс теперь терминальный ACP-клиент, а не прежний UI через HTTP-шлюз.

## Happ и конфигурация

Включите Happ и проверьте порты. Шаблон `app/config.example.json` используется, если отсутствует локальный `app/config.json`:

```json
{
  "http_proxy": "http://127.0.0.1:10809",
  "socks_proxy": "socks5h://127.0.0.1:10808",
  "default_model": "",
  "fallback_http_proxies": [],
  "routing": "proxy"
}
```

Прокси-переменные задаются только дочернему агенту. Если HTTP-порт недоступен, запуск завершается. Автоматического прямого соединения, DNS/SNI-прокси или переключения на резервный выход нет. Старое `routing: auto` преобразуется в `proxy` в памяти; `smart_dns` требует исправить конфиг. Непустой `fallback_http_proxies` теперь отклоняется. Никакие системные DNS, маршруты, сертификаты или настройки Zed не меняются.

Это настройка прокси для процесса, а не сетевая песочница. Выбор VPN-сервера и маршрута после локального прокси контролирует Happ. Браузер авторизации имеет собственные сетевые настройки. Передача HTTPS_PROXY агенту не доказывает доступность региона или успешную генерацию.

## Проверки

- `./agym check --offline`: платформа и SHA256 Google ACP/harness, без сети и запуска агента.
- `./agym check`: доступность порта Happ и настоящее ACP-рукопожатие; без входа и проверки аккаунта.
- `./agym check --model-test`: явно запрашиваемый тест реальной модели через ACP, использует квоту. Запрос синтетический, рабочая папка временная. Для конкретной модели добавьте `--probe-model ID`.

В каждой сессии хеши ACP и harness сверяются с манифестом до запуска. Подменённый бинарник не запускается. Источники и сравнение с Zed описаны в [аудите интеграции](docs/ZED-ACP-AUDIT.md).

## Профиль и ограничения

Официальный агент использует отдельный `app/profile/gemini`; обёртка не открывает его файлы авторизации. Профиль Zed, системный аккаунт и существующие локальные токены не удаляются и не копируются. Для входа используйте `./agym login` после восстановления доступа к сервису. Повторный вход не снимает серверный 403.

Клиент называется `agycli-terminal` и объявляет только реализованные возможности. Возможности Zed (редакторские буферы, терминалы и формы) не имитируются. Доступность сторонних моделей и регионов определяет Google; терминальный клиент не получает автоматически возможности, разрешённые только конкретным редакторам. Одинаковый ACP-механизм не означает официальную сертификацию этой обёртки и не гарантирует отсутствие ограничений аккаунта.

`app/profile`, `app/config.json`, логи и история исключены из git и чистой сборки. Не публикуйте их. `agym update` обновляет git-установку только при отсутствии локальных изменений; обновление не коммитит ваш код. `./agym install` создаёт симлинк в `~/.local/bin`, после чего доступен `agym` из любой папки.

Windows-скрипты подготовлены, но реальный запуск Windows-бинарника на Windows не проверен.
