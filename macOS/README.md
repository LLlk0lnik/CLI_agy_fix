# agyCLI — macOS на Apple Silicon (M1/M2/M3/M4 и новее, ARM64)

Переносимый запуск обычного Antigravity CLI через собственный локальный шлюз и отдельную авторизацию. Запасной ACP-клиент также включён. Это не официальный дистрибутив Google; оригинальные бинарники Google не изменены.

```text
README.md
agym              — единая CLI-команда со всеми флагами и шорткатами
Run-AGY.command   — обычный CLI через VPN/шлюз
Run-ACP.command   — отдельный ACP-клиент
setup/            — Login и Check
app/              — код, runtime, config и локальный профиль
docs/             — README-AI и сведения о компонентах
```

## Быстрый старт с `agym`

Для максимального удобства используйте команду `agym`:

```bash
# 1. Дать права на запуск
chmod +x ./agym ./*.command setup/*.command app/runtime/*

# 2. Установить в PATH (симлинк в ~/.local/bin/agym)
./agym install

# 3. Проверить работу Happ и окружения
agym check

# 4. Войти в Google-аккаунт
agym login

# 5. Запустить в текущей папке
agym

# Или запустить без лишних запросов подтверждений прав (yolo-режим):
agym -y
```

## Установка с самого начала

### 1. Получить agy — Antigravity CLI

Официальная инструкция и скачивание: [Google Antigravity](https://antigravity.google/docs/getting-started).
В этом архиве **agy 1.4.12 уже скачан** и находится в `app/runtime/agy`. Поэтому для этой сборки отдельная установка CLI не нужна: используются именно вложенные бинарники, независимо от установленного в системе agy.

Если нужен и обычный системный agy, его официальный установщик запускается так:

```bash
curl -fsSL https://antigravity.google/cli/install.sh | bash
```

Это необязательный шаг и он может добавить agy в системное окружение пользователя. Наши запуски не вызывают установщик и не меняют PATH. Команда просто `agy` запустит обычную установленную версию, а `agym` — эту модифицированную сборку через Happ.

### 2. Установить Python

Скачайте Python 3.11 или новее с [python.org](https://www.python.org/downloads/). Сторонние Python-пакеты и pip install не нужны.
Установите официальный пакет Python для macOS; не удаляйте системные компоненты macOS. После установки откройте новое окно Terminal.

Проверьте:

```bash
python3 --version
```

### 3. Установить и настроить Happ

Скачайте Happ с [happ.info](https://happ.info/) и добавьте свою рабочую конфигурацию или подписку. В настройках Happ найдите входящие локальные порты.

Откройте `app/config.json` и при необходимости укажите ваши реальные порты Happ:

```json
{
  "http_proxy": "http://127.0.0.1:10809",
  "socks_proxy": "socks5h://127.0.0.1:10808",
  "default_model": "gemini-3.8-flash-high"
}
```

Адреса должны оставаться локальными (`127.0.0.1`), без паролей в этом файле.

### 4. Проверить установку и сеть

```bash
agym check
# или ./setup/Check.command
```

Проверка ищет три бинарника, проверяет архитектуру, HTTPS через Happ и ACP initialize. На чистой сборке сообщение «NEXT: run Login» нормально: своего профиля пока нет. Проверка сама не входит в аккаунт.

### 5. Войти под своим аккаунтом Google

```bash
agym login
# или ./setup/Login.command
```

Завершите вход в открывшемся браузере и дождитесь «Вход завершён». Если окно не открылось, используйте показанную ссылку входа. У браузера свои настройки сети; proxy-переменные действуют на агент, а не на уже открытый браузер.

Нужен собственный аккаунт с доступным действующим тарифом/проектом. Чужая подписка не передаётся вместе с архивом. Сборка не создаёт права доступа и не гарантирует, что любой аккаунт будет принят Google.

### 6. Запуск и флаги `agym`

```bash
# Интерактивный диалог в текущей папке
agym

# Режим авто-одобрения (пропускает вопросы на выполнение команд/прав)
agym -y
agym yolo

# Одиночный запрос
agym -p "Ответь одним словом: привет"

# Продолжить предыдущий разговор
agym -c

# Текстовый ACP-клиент
agym acp
```

## Где данные и что изолировано

Папка `app/profile` появляется только после первого использования. Авторизация ACP: `app/profile/gemini/antigravity-acp`. История и настройки штатного CLI: `app/profile/native-home`. Диагностика ACP: `app/profile/server.log`. Keychain для ACP отключён; используется файловое хранилище.

На macOS файлы профиля создаются с ограниченными UNIX-правами (`0700`).

Настройки окружения действуют только в процессе запуска и его потомках. Системные профили и глобальный agy не затрагиваются.

## FAQ

### Нужно ли иметь `agy` на машине изначально?
**Нет, не нужно.**
Официальный бинарник `agy` (1.4.12) уже предустановлен внутри пакета в папке `app/runtime/agy`. Скрипт `agym` всегда обращается именно к этому файлу. Если у вас уже есть системная установка `agy`, они изолированы друг от друга и не конфликтуют.

### Можно ли запускать `agym` из любой папки проекта?
**Да, из любой.**
После запуска `./agym install` симлинк добавляется в `~/.local/bin/agym`. Переходите в любую папку проекта (`cd ~/my-project`) и запускайте `agym` (или `agym -y`) — агент автоматически подхватывает текущую директорию.

## Обновление токенов и ошибка 401

Шлюз обновляет access token до истечения срока и проверяет время после длительного простоя. Если Google отклоняет запрос с HTTP 401, шлюз обновляет токен и повторяет этот запрос ровно один раз. Параллельные запросы используют общее обновление. Загрузка каталога моделей и генерация берут актуальный токен. 403, сетевые ошибки и уже начавшаяся передача ответа автоматически не переигрываются.

Если сам refresh token отозван или просрочен (invalid_grant), нужен повторный вход: `setup/Login.command`. Перезапустите работающий CLI после обновления кода. Новые тесты используют только искусственные токены; длительное ожидание истечения реального токена не требуется.
